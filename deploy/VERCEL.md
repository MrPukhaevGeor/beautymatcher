# Демо на Vercel через GitHub

Только демо: `DEMO_MODE=true`, вымышленные данные. Vercel и база Neon находятся не в России, поэтому настоящие заявки и персональные данные сюда нельзя (152-ФЗ). Режим `DEMO_MODE=false` на Vercel не включать.

Кто делает: **[вы]** входы, авторизация GitHub, значения секретов. **[я]** локальные команды git и node.

## Ограничения, которые нужно знать

- **Тариф Hobby: только личное некоммерческое использование.** Подходит ли он для проекта, который вы показываете городу, решаете вы по правилам Vercel.
- **Блокировка деплоя по автору коммита.** На Hobby с приватным репозиторием Vercel может заблокировать деплой, если автор коммита не сопоставляется с вашим аккаунтом. Поэтому новые коммиты идут с адресом noreply вашего GitHub-аккаунта. Если деплой всё равно блокируется, причина будет указана в панели или в письме от Vercel.
- **Нет постоянного диска.** Загрузка фото в файловую систему на Vercel не работает. В демо фото отключены, для настоящего запуска всё равно нужно российское размещение.
- **Cron на Hobby раз в сутки,** время срабатывания плавает в пределах часа. Для ночного сброса этого достаточно.

## 1. Что я делаю до импорта [я]

Импорт сразу собирает `main`, а каждый следующий push в `main` становится рабочим деплоем. Поэтому сначала я проверяю всё локально (сборка, типы, тесты) и отправляю на GitHub одним коммитом. Каждую отправку согласуем отдельно.

## 2. Импорт проекта [вы]

1. На vercel.com войдите через GitHub. Add New → Project → выберите репозиторий `beautymatcher`. Доступ приложению Vercel давайте **только к этому репозиторию**.
2. Framework определится как Next.js. Команды сборки не меняйте: `npm run build` уже запускает `prisma generate`.
3. Перед первым Deploy, в блоке Environment Variables, задайте:

   | Переменная | Значение |
   | --- | --- |
   | `DEMO_MODE` | `true` |
   | `SESSION_SECRET` | новый случайный секрет (команда ниже) |
   | `CRON_SECRET` | другой новый случайный секрет |
   | `SITE_URL` | `https://<адрес проекта>.vercel.app`, если ещё неизвестен, поставьте после первого деплоя и сделайте Redeploy |

   Секреты в чат не присылайте.

Генерация секрета без вывода на экран (PowerShell), результат окажется в буфере обмена. Запустите дважды: для `SESSION_SECRET` и для `CRON_SECRET`.

```powershell
$b = New-Object byte[] 32; [Security.Cryptography.RandomNumberGenerator]::Create().GetBytes($b); (($b | % { $_.ToString('x2') }) -join '') | Set-Clipboard
```

## 3. База данных [вы]

1. В проекте Vercel: Storage → Create Database → Neon (Marketplace). Подключите её к этому проекту. Войти и принять условия нужно вам.
2. Регион: посмотрите в Settings → Functions, какой регион у функций, и создайте базу в ближайшем к нему. Данные будут идти через океан, если регионы далеко друг от друга.
3. Интеграция сама добавит переменные. Откройте Settings → Environment Variables и проверьте, что есть `DATABASE_URL` (через пул подключений, он нужен сайту) и `DATABASE_URL_UNPOOLED` (прямой адрес, он нужен для схемы). Точные имена зависят от версии интеграции, ориентируйтесь на то, что видите в панели.

## 4. Таблицы и демо-данные, один раз [вы + я]

1. **[вы]** Скопируйте значение `DATABASE_URL_UNPOOLED` в файл `.env.neon` в корне проекта, одной строкой `DATABASE_URL_UNPOOLED=<значение>`. Файл в `.gitignore`, в чат значение не присылайте.
2. **[я]** `node deploy/remote-init.mjs --dry-run` проверит файл и ничего не применит. Затем `node deploy/remote-init.mjs` применит схему и демо-данные. Скрипт откажется работать с локальной базой, с чужим хостом и с адресом через пул.
3. **[вы]** После этого удалите `.env.neon`.
4. **[вы]** В Vercel сделайте Redeploy последнего деплоя, чтобы сайт увидел базу и `SITE_URL`.

## 5. Проверка на живом адресе

- `https://<адрес>/api/health` отвечает `{"ok":true}`.
- Виден баннер «Демо-версия», `/robots.txt` содержит `Disallow: /`.
- Демо-вход работает. Это подтверждает, что cookie с флагом `secure` принимается по https.
- Проходит цепочка: заявка модели, подтверждение школой.
- Адрес `/api/cron/reset` без заголовка отвечает 401 (проверка: откройте его в браузере).
- Ночной сброс: оставьте на сайте тестовый отзыв, затем в панели Vercel откройте Settings → Cron Jobs и запустите задачу вручную. Тестовые данные должны исчезнуть.
- **Откройте адрес с телефона в мобильной сети, без VPN.** Ваш компьютер работает через VPN, поэтому его браузер ничего не доказывает про доступность из России. Школам ссылку отправляйте только после этой проверки.

## 6. Свой домен

Vercel покажет нужные DNS-записи в Settings → Domains после добавления `krasotaryadom.ru` или поддомена. Какие именно записи нужны и поддерживает ли их reg.ru, смотрите в панели Vercel. Для правок DNS в reg.ru нужна идентификация владельца через Госуслуги.

## 7. Если что-то пошло не так

- **Деплой заблокирован из-за автора коммита:** причина указана в панели или письме. Проверьте, что вход в Vercel сделан через тот же GitHub-аккаунт, и что в последнем коммите автор с адресом noreply этого аккаунта.
- **Сайт открывается, но страницы с данными отдают ошибку:** не применены таблицы (шаг 4) или не сделан Redeploy после подключения базы.
- **`Too many connections`:** уменьшите `DB_POOL_MAX` (по умолчанию 3) или убедитесь, что сайт использует адрес через пул.
